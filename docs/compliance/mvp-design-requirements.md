# Consolidated Compliance Design Requirements — Platform Foundation MVP

- **Document:** `docs/compliance/mvp-design-requirements.md`
- **Status:** Baseline v1 — 2026-07-08
- **Author:** Architect Agent (lifecycle step 4 — consolidation)
- **Inputs:** `docs/compliance/nis2-obligations.md` (NIS2-REQ-1..16), `docs/compliance/dora-obligations.md` (COMP-1..13), `docs/compliance/gdpr-obligations.md` (GDPR-01..18), `docs/prd/platform-foundation-mvp.md` (AC-1..AC-91)
- **Purpose:** single de-duplicated requirements set to fold into the `platform-foundation-mvp` acceptance criteria and backlog. Every [must]/[should] finding from the three obligation maps is represented exactly once. Where regulations overlap, the strictest label and earliest phase win.

Legend — **Label:** strictest across contributing findings ([must] beats [should]; `should→must @ <trigger>` = should now, hard requirement at the stated trigger). **Phase:** MVP = fold into platform-foundation-mvp ACs now; pre-GA = scheduled backlog before general availability / first paying EU (or FE) customer; ORG = organizational track (non-engineering). Split phases (e.g., "MVP: hook / pre-GA: full") preserve the source docs' own splits.

## 2. Phasing Split

### 2a. MVP-blocking (fold into platform-foundation-mvp acceptance criteria now)

Engineering/design work in the current cycle; retrofit is expensive or the MVP already builds the surface these constrain.

- **Decisions gating design (see §4):** CR-1 (residency/OQ-7), CR-2 + CR-3 (LLM region + terms — model choice is being made now).
- **New ACs:** CR-6 (encryption at rest + crypto policy), CR-7 (backup jobs; restore drill is pre-GA), CR-8 (incident record + classification), CR-9 (blast-radius query + tenant-impact attribution on ops alerts), CR-10 (verified security-notification contact + mass-notify procedure), CR-16 (internal operator role + MFA), CR-17 (CVD/security.txt), CR-18 (agent update-channel ACs), CR-15 (records of processing, document).
- **Extensions/constraints on existing ACs:** CR-11 purge completeness (extends AC-10 to all stores and all offboarding), CR-12 audit minimization (constrains AC-83/84), CR-13 DPA acceptance in signup (extends AC-1/AC-3), CR-14 FE flag (tenant settings hook only), CR-19 FP-export pseudonymization (constrains AC-46), CR-20 evidence-completeness contract test (verifies AC-74 et al.), CR-23 schema privacy annotation (rides the OQ-3 schema contract), CR-24 k-anonymity breached-password check (constrains AC-1), CR-4 triage disclosure (documents AC-48/52), CR-5 sub-processor register document naming the actual LLM provider.
- **Design hooks only (build later, don't preclude):** CR-10 automated notifier consumes CR-9 impact records; CR-11 bulk export must not be precluded by storage choices; CR-22 prompt-builder must expose a minimization/redaction hook.

### 2b. Pre-GA backlog (before general availability / first paying EU or FE customer)

Sequenced by lead time — CR-27 (certification) first, it takes 6–12 months.

- CR-27 third-party assurance (start immediately), CR-26 external pentest, CR-7 tested restore drill + BCP/DR doc, CR-10 automated out-of-band notification pipeline (resolves OQ-6 fully), CR-11 bulk export + paid-tenant offboarding terms, CR-5 full supplier register + automated change notification, CR-8 full breach runbook + tabletop, CR-14 DORA addendum live in self-serve flow, CR-21 data-subject search/export (must @ GA), CR-22 prompt minimization/pseudonymization, CR-25 console TOTP MFA (must before first essential-entity customer), CR-28 committed customer-visible SLAs, CR-23 tenant-configurable command-line redaction.

### 2c. Organizational track (non-engineering; start now, mostly cheap)

- **Legal counsel (external):** DPA drafting + SCC execution (CR-13), DORA addendum drafting (CR-14), LLM provider contract negotiation (CR-3), TLPT policy (CR-30).
- **Corporate/CEO:** establishment/jurisdiction decision, EU representatives (GDPR Art. 27 + NIS2 Art. 26(3)), NIS2 registration readiness incl. service IP-range record (CR-32); LEI acquisition + Annex III service-code determination + register-of-information data pack (CR-31); management-body approval of the measure set (CR-35).
- **DPO:** Art. 37 analysis and appointment (CR-33).
- **Governance/process:** ISMS-lite policy + risk register (CR-34), training program with records (CR-36), competent-authority cooperation procedure (CR-29), NIS2 Art. 24/EUCS certification watch — quarterly (inside CR-27).
